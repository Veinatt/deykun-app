# Объяснение структуры проекта Deykun Marketing

## 🎯 Цель проекта

Переписать лендинговую страницу с HTML/CSS/JS на современный стек React + TypeScript + Vite с подготовкой к интеграции с Directus CMS.

## 📁 Структура проекта - что зачем и почему

### `/src/types` - Типизация данных

**Зачем:** Определяет структуру всех данных, которые будут приходить из Directus API.

**Почему:**

- TypeScript требует типов для безопасности кода
- Готовность к интеграции с Directus - все типы соответствуют структуре коллекций CMS
- Централизованное управление типами упрощает поддержку

**Что внутри:**

- `content.types.ts` - типы для контента (HeroContent, Rate, CaseStudy, Review, FAQItem и т.д.)
- `index.ts` - центральный экспорт + типы для Redux

---

### `/src/store` - Redux хранилище

**Зачем:** Централизованное управление состоянием приложения.

**Почему Redux:**

- Глобальное состояние доступно из любого компонента
- Предсказуемое управление состоянием
- Интеграция с Redux DevTools для отладки

**Что внутри:**

- `store.ts` - конфигурация Redux store
- `hooks.ts` - типизированные хуки (useAppDispatch, useAppSelector)
- `slices/` - отдельные слайсы для разных частей состояния:
  - `modalSlice.ts` - состояние модальных окон (открыто/закрыто, тип, данные)
  - `formSlice.ts` - состояние форм (отправка, ошибки, успех)
  - `uiSlice.ts` - UI состояние (меню, скролл, активные табы/аккордеоны)

**Пример использования:**

```typescript
// В компоненте
const isMenuOpen = useAppSelector((state) => state.ui.isMenuOpen);
const dispatch = useAppDispatch();
dispatch(toggleMenu());
```

---

### `/src/services` - API сервисы

**Зачем:** Инкапсуляция логики работы с внешними API.

**Почему:**

- Разделение ответственности - компоненты не знают о деталях API
- Легко заменить моковые данные на реальные запросы
- Централизованная обработка ошибок

**Что внутри:**

- `api.ts` - функции для получения данных из Directus (сейчас моковые данные)
- `formService.ts` - отправка форм, валидация, форматирование телефонов

**Будущая интеграция:**

```typescript
// Сейчас (мок):
const hero = await getHeroContent(); // возвращает моковые данные

// После интеграции с Directus:
// Раскомментировать реальные запросы в api.ts
const hero = await getHeroContent(); // запрос к Directus API
```

### `/src/components` - React компоненты

#### `/layout` - Компоненты макета

**Header** - Шапка сайта

- Бургер-меню для мобильных устройств
- Управление через Redux (uiSlice)
- Анимации через Framer Motion
- Интеграция с модальным окном заявки

**Footer** - Подвал сайта

- Контакты, соцсети, копирайт

#### `/sections` - Секции главной страницы

Каждая секция - отдельный компонент:

- **HeroSection** - главный экран
- **PurposeSection** - "Для чего это нужно?"
- **WhyUsSection** - "Почему именно мы?"
- **ServicesSection** - тарифы с табами
- **PortfolioSection** - кейсы со Swiper
- **ReviewsSection** - отзывы
- **FAQSection** - FAQ с аккордеонами
- **ContactSection** - контакты и форма

**Почему отдельные компоненты:**

- Модульность - легко добавлять/удалять секции
- Переиспользование - можно использовать на других страницах
- Изоляция стилей через CSS Modules

#### `/ui` - Переиспользуемые UI компоненты

**Button** - Универсальная кнопка

- Варианты: primary, secondary, outline, ghost
- Размеры: small, medium, large
- Анимации через Framer Motion
- Поддержка метки скидки

**Modal** - Модальное окно

- Управление через Redux (modalSlice)
- Форма заявки внутри
- Анимации появления/исчезновения

**Accordion** - Аккордеон для FAQ

- Управление через Redux или локальное состояние
- Анимации раскрытия/сворачивания
- Поддержка множественного открытия

**Tabs** - Табы для категорий

- Управление через Redux (uiSlice)
- Переключение между категориями тарифов
- Анимации переключения

**Swiper** - Обертка для Swiper.js

- Предустановленные настройки
- Поддержка автопрокрутки, навигации, пагинации
- Различные эффекты (slide, fade, cube)

#### `/shared` - Общие компоненты

**RequestForm** - Форма заявки

- Используется в модалке и на странице
- Валидация через React Hook Form + Yup
- Интеграция с Redux для состояния отправки

---

### `/src/pages` - Страницы приложения

**HomePage** - Главная страница

- Собирает все секции вместе
- Прокрутка к секциям по якорям

**SuccessPage** - Страница успеха

- Показывается после успешной отправки формы
- Ссылка на главную

**ErrorPage** - Страница ошибки

- Показывается при ошибке отправки формы
- Возможность повторить отправку

**Почему отдельные страницы:**

- Роутинг через React Router
- Разные состояния приложения требуют разных страниц
- SEO-friendly структура

---

### `/src/hooks` - Кастомные React хуки

**Зачем:** Переиспользуемая логика компонентов.

**Что внутри:**

- `useFormSubmit` - логика отправки форм
- `useScrollPosition` - отслеживание позиции скролла
- `useToggle` - переключение boolean состояния

**Почему хуки:**

- Переиспользование логики между компонентами
- Чистый код - логика отделена от UI
- Легко тестировать

---

### `/src/utils` - Утилиты

**constants.ts** - Константы приложения

- Конфигурация (название, email, телефон)
- Маршруты навигации
- Ссылки на соцсети
- Брейкпоинты для адаптива

**helpers.ts** - Вспомогательные функции

- Форматирование данных
- Валидация
- Обработка строк

**Почему отдельно:**

- Централизованное хранение констант
- Легко изменить конфигурацию в одном месте
- Переиспользование функций

---

### `/src/styles` - Глобальные стили

**globals.scss** - Главный файл

- Импортирует все остальные стили
- Подключается в main.tsx

**\_variables.scss** - SCSS переменные

- Цвета (primary, secondary, accent)
- Шрифты и размеры
- Отступы и брейкпоинты
- Тени и скругления

**\_mixins.scss** - SCSS миксины

- Переиспользуемые стили
- Адаптивные миксины

**\_reset.scss** - Сброс стилей браузера

- Нормализация стилей
- Базовые стили для элементов

**Почему SCSS:**

- Переменные и миксины для переиспользования
- Модульность через CSS Modules
- Легко поддерживать единый стиль

## 🔄 Поток данных

1. **Пользователь взаимодействует с UI** → действие диспатчится в Redux
2. **Redux обновляет состояние** → компоненты перерисовываются
3. **Компоненты получают данные** → через props или из Redux
4. **API запросы** → через сервисы (сейчас моки, потом Directus)

## 🎨 Анимации

**Framer Motion** используется для:

- Плавного появления элементов при скролле
- Анимаций кнопок (hover, click)
- Переходов между состояниями (модалки, меню)
- Анимаций аккордеонов и табов

## 📱 Адаптивность

- Mobile-first подход
- Брейкпоинты определены в `_variables.scss`
- Бургер-меню для мобильных устройств
- Адаптивные компоненты через CSS Grid/Flexbox

## 🚀 Готовность к Directus
